# Product overview

## Confirmed context

The intended product is:

- a photo-sharing social network;
- cross-platform;
- federated, so users may belong to independently operated servers that can
  communicate with one another; and
- inspired by Pixelfed and broadly comparable to Instagram in its focus on
  social photo sharing.

These comparisons communicate product direction only. They do not imply that
the project will copy another product's complete feature set, architecture, or
implementation.

## Current phase and boundary

The repository is establishing the environment in which the product can later
be built. It should capture knowledge as that knowledge becomes reliable. The
current phase does not include implementing the application or choosing missing
architecture details by assumption.

## Open questions

The following are intentionally unresolved:

- target platforms and the meaning of cross-platform for the first release;
- initial user journeys and minimum product scope;
- federation protocol, compatibility goals, and cross-server behavior;
- identity, account discovery, privacy, safety, moderation, and server
  governance requirements;
- media storage, processing, delivery, and accessibility requirements;
- client, server, data, deployment, observability, and security architecture;
- programming languages, frameworks, infrastructure, and third-party services;
- testing, release, contribution, and operational processes.

Resolve these through product discovery and explicit decisions. When an answer
becomes confirmed product context, update this document. When it is a
consequential choice with alternatives and tradeoffs, add a decision record.

## Non-goals for this phase

- Producing a complete feature specification
- Scaffolding application or infrastructure code
- Selecting technologies without an explicit decision process
- Treating inspiration from existing products as a requirement to duplicate
  them
